# Release Procedure

Use this checklist for every change and release. Do not skip the clean-build and
uploaded-asset verification steps.

## Versioning

Follow semantic versioning:

- Patch, for example `1.1.1`: bug fixes, small UI copy changes, tiny visual tweaks, no behavior change.
- Minor, for example `1.2.0`: new features, meaningful UI refreshes, performance work, internal rewrites that keep user workflows compatible.
- Major, for example `2.0.0`: incompatible settings, changed hotkey behavior, removed workflows, or other breaking user-facing changes.

For a full implementation rewrite that keeps the same feature set and settings
compatibility, use a minor bump.

## Pre-Change Checks

1. Confirm the repo and branch:

   ```powershell
   git status --short
   git branch --show-current
   git remote -v
   ```

2. Inspect existing version references before editing:

   ```powershell
   rg -n "version =|v[0-9]+\.[0-9]+\.[0-9]+|[0-9]+\.[0-9]+\.[0-9]+" Cargo.toml Cargo.lock src README.md
   ```

3. Preserve unrelated user changes. Do not reset, checkout, or delete files unless the user explicitly asked for it.

## Required Version Updates

For a release version `X.Y.Z`, update all relevant locations:

- `Cargo.toml`: package `version = "X.Y.Z"`
- `Cargo.lock`: regenerated by Cargo after build/test
- `src/main.rs`: visible UI version label, if present, such as `vX.Y.Z`
- `README.md` or other docs, only if they mention the version

Then verify no old version string remains in source:

```powershell
rg -n "OLD_VERSION|vOLD_VERSION" Cargo.toml Cargo.lock src README.md
```

## Build And Test

Always format and test:

```powershell
cargo fmt
cargo test
```

For release builds, always clean first to avoid stale embedded strings or stale
resources:

```powershell
cargo clean
cargo build --release
```

Verify the executable exists:

```powershell
Get-Item .\target\release\windowmanagerapp.exe | Select-Object FullName,Length,LastWriteTime
```

## Binary Verification

Before committing or uploading, scan the compiled executable for both the old
and new visible version strings:

```powershell
rg -a -n "vOLD_VERSION|vNEW_VERSION|OLD_VERSION|NEW_VERSION" .\target\release\windowmanagerapp.exe
```

The output must contain the new version and must not contain the old visible UI
version. If the old version appears, run `cargo clean` and rebuild again.

Run a short startup smoke test:

```powershell
$exe = Join-Path (Get-Location) 'target\release\windowmanagerapp.exe'
$p = Start-Process -FilePath $exe -WindowStyle Hidden -PassThru
Start-Sleep -Seconds 4
$proc = Get-Process -Id $p.Id -ErrorAction SilentlyContinue
if ($proc) {
  [PSCustomObject]@{
    Started = $true
    StayedAlive = $true
    WorkingSetMB = [math]::Round($proc.WorkingSet64 / 1MB, 2)
    PrivateMB = [math]::Round($proc.PrivateMemorySize64 / 1MB, 2)
    Bytes = (Get-Item $exe).Length
  }
  Stop-Process -Id $proc.Id -Force
} else {
  [PSCustomObject]@{ Started = $true; StayedAlive = $false }
}
```

## Commit And Tag

Check the final diff:

```powershell
git status --short
git diff -- Cargo.toml Cargo.lock src README.md
```

Commit:

```powershell
git add Cargo.toml Cargo.lock src README.md RELEASE_PROCEDURE.md
git commit -m "Release vX.Y.Z"
```

Create an annotated tag:

```powershell
git tag -a vX.Y.Z -m "vX.Y.Z"
```

Push:

```powershell
git push origin main
git push origin vX.Y.Z
```

## GitHub Release

Create or update the GitHub release for tag `vX.Y.Z`.

Upload the release asset with the stable asset name:

```text
windowmanagerapp.exe
```

Do not include credentials, tokens, or secrets in scripts, docs, commits, issue
comments, or release notes.

Suggested release-note format:

```text
Short release summary.

- User-facing change 1.
- User-facing change 2.
- Performance, size, compatibility, or reliability note.
```

## Uploaded Asset Verification

After uploading, download the release asset back from GitHub and scan that exact
downloaded file:

```powershell
$url = 'https://github.com/filip-porebski/Window-Manager-App/releases/download/vX.Y.Z/windowmanagerapp.exe'
$tmp = Join-Path $env:TEMP 'windowmanagerapp-vX.Y.Z-check.exe'
Invoke-WebRequest -Uri $url -OutFile $tmp
rg -a -n "vOLD_VERSION|vNEW_VERSION|OLD_VERSION|NEW_VERSION" $tmp
Remove-Item -LiteralPath $tmp -Force
```

The downloaded asset must contain the new version and must not contain the old
visible UI version. If it is wrong, delete and re-upload the release asset, then
repeat this verification.

## Final Response Checklist

Tell the user:

- Chosen version and why, if relevant.
- Commit hash.
- Tag.
- Release URL.
- Download URL.
- Tests/build/smoke test results.
- Whether the working tree is clean.
